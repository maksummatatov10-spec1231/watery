# Подключение Watery к Horizon — подтверждённые исходники

Снимок: `reference/horizon-source.json`; исходники `vendor/horizon/`.
Не подтверждено, что установленная у пользователя игра соответствует этому коммиту.

## Отрисовка и вычисления

`crates/horizon-client-render/src/gfx/native_render.rs:51`:
`WorldDrawn` даёт device, queue, encoder, color/color_view/color_format,
размеры, depth, матрицы камеры. `RenderHooks::world_drawn` вызывается после
рисования мира до руки и интерфейса. Нужно запросить `world_depth` через
`render_needs`. Depth32Float имеет обратную глубину, небо равно 0;
размер depth может отличаться от color. Перед чтением color нужна копия.
Это позволяет собственные compute-проходы и композицию поверхности, но
не подтверждает включение жидкости в отражения, тени и историю TAA мира.
HDR требует сохранения значений выше 1 и альфа-канала.

Оригинальные compute GLSL переводятся утилитой `tools/shader-port` через
Naga 30.0.1 из этого снимка Horizon. Успех означает только проверенный IR
и повторно разобранный WGSL, не эквивалентность физики и не запуск GPU.
Отчёт `reference/shader-port-report.md` перечисляет также ошибки.
Write-only доступ расширен до read_write без добавления чтений;
WorkGroupSize.x заменён исходным литеральным размером группы;
скалярные проверки NaN/Inf в двух CG-проходах проверяют биты экспоненты.
Подгруппы и coherent-барьеры НЕ заменены последовательными заглушками.
Два решателя используют 1024 потока на группу — лимит устройства необходимо
проверить до создания pipeline; уменьшать размер без адаптации циклов нельзя.

## Рабочие потоки

`crates/horizon-client/src/game/native_tasks.rs` реализует постоянный пул
модов (по умолчанию 1–4 потока), отдельный от генерации чанков.
`HostTaskExt::spawn_task_with` в `src/mod_api.rs:1143` передаёт результат
обратно потоку Game во время native_tick. Нельзя изменять мир из рабочего
потока. `native_chunk_snapshot` возвращает переносимый снимок уже загруженного
чанка без загрузки/генерации отсутствующего.

Предположение об отсутствующем публичном API пула опровергнуто исходником:
`crates/horizon-mod-api-gen/src/lib.rs:1039–1063` объединяет helpers из
`native-hooks.json` И `tools/native-hook-fragments/*.json`; фрагмент
`mod_async_worker.json` содержит spawn_task/defer_main_thread.
Полная генерация/компиляция Host пока не проверена.

`crates/horizon-client-render/src/gfx/surface_setup.rs:126–168` запрашивает
лимиты адаптера и поддерживаемый `SUBGROUP`, как автономная GPU-проверка.
Это устраняет подозрение, что сам исходный Horizon ограничивает группу
до 256 потоков; лимиты конкретного устройства всё равно проверяются.
Автономный запуск не заменяет сборку мода с Host.

## Упаковка

Документация `docs/mods.md:7–8,625–628` описывает `.hnmod` как пакет исходного
Rust-кода для сборки игры лаунчером, не DLL и не JAR. Исходники публикуются
в репозитории, пакет прикладывается к GitHub Release. `docs/native-mods.md`
также описывает новый объединённый `.hmod` с native manifest: поэтому нельзя
проверять тип мода только по расширению. Для согласованного выпуска этого
порта выбран `.hnmod`; упаковки и выпуска пока нет.

## Осталось реализовать

Управление GPU-буферами и проходами всех материалов, перенос оставшихся
шейдеров и графических проходов, источники/вёдра/блоки, коллизии и сущности,
взрывы и реакции лавы, сеть, сохранение, команды, интерфейс/звук и запись.
Затем сборка с Horizon, игровые сравнения с исходным Watery и измерения
CPU/GPU/памяти. Ни автономные тесты, ни компиляция шейдеров их не заменяют.
